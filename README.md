# Сайт Дмитрушківського ліцею (GitHub Pages)

Сайт зберігає **структуру меню** старого Google Sites (62 сторінки + 3 зовнішні посилання, до 3 рівнів вкладеності),
працює на безкоштовному хостингу **GitHub Pages**, а адміністратор може **змінювати тексти, меню та завантажувати файли
прямо з сайту** — на сторінці `/admin/`. Ніякого власного сервера й програмування для цього не потрібно.

---------------------------------------------------------------------

## 1. Як влаштовано

| Що | Де лежить |
|---|---|
| Меню, налаштування (назва, адреса, банери, партнери…) | `content/site.json` |
| Текст кожної сторінки (Markdown) | `content/pages/<адреса>.md` |
| Завантажені документи та зображення | `uploads/` |
| Публічний сайт | `index.html`, `assets/` |
| Адмін-панель | `admin/` |
| Скрипт перенесення зі старого сайту | `tools/migrate_google_sites.py` |

Адмін-панель змінює ці файли в репозиторії через GitHub API **одним записом (комітом)**. GitHub Pages сам оновлює сайт
за 1–2 хвилини. Уся історія змін зберігається — будь-яку правку можна скасувати.

## 2. Запуск на GitHub Pages (один раз)

1. Зареєструйтеся на [github.com](https://github.com) і створіть **публічний** репозиторій, наприклад `dmlsayt-site`
   (GitHub Pages безкоштовно працює з публічними репозиторіями).
2. Завантажте в нього **весь вміст цієї папки** (включно з прихованим файлом `.nojekyll`).
   * Через веб-інтерфейс: *Add file → Upload files*. Завантажувати можна до 100 файлів за раз, тож робіть це порціями
     (спочатку `assets`, `admin`, `index.html`, потім `content/pages`, `uploads`), або скористайтеся програмою **GitHub Desktop**
     чи командою `git push` — вона не має такого обмеження.
3. У репозиторії: *Settings → Pages → Build and deployment → Deploy from a branch → Branch: `main`, папка `/ (root)` → Save*.
4. Через 1–2 хвилини сайт відкриється за адресою `https://ВАШ-ЛОГІН.github.io/dmlsayt-site/`,
   а адмін-панель — `https://ВАШ-ЛОГІН.github.io/dmlsayt-site/admin/`.

Власний домен (наприклад, `dmlicey.edu.ua`) підключається в *Settings → Pages → Custom domain*.

## 3. Адмін-панель

### 3.1. Створіть ключ доступу (токен) — один раз для кожного адміністратора
1. На github.com: *Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token*.
2. Назва — «Сайт ліцею», строк дії — наприклад, 1 рік.
3. *Repository access → Only select repositories* → оберіть репозиторій із сайтом.
4. *Repository permissions → **Contents → Read and write*** (інших прав не потрібно).
5. *Generate token* і скопіюйте значення (починається з `github_pat_`). Показується лише один раз.

Інші адміністратори мають **власний акаунт GitHub**, доданий у репозиторій: *Settings → Collaborators → Add people*.

### 3.2. Щоденна робота
1. Відкрийте `…/admin/`, вкажіть репозиторій (`логін/dmlsayt-site`) і токен → **Увійти**.
2. **Сторінки та меню** — виберіть сторінку, змініть текст. Кнопки над полем тексту:
   заголовки, списки, посилання, **Зображення**, **Файл** (PDF/Word/Excel), **Відео** YouTube,
   **Документ Google** (вбудувати файл із Диску), таблиця. Праворуч — живий перегляд.
3. Меню: **↑ ↓** — порядок; **→** — зробити підпунктом попереднього; **←** — винести на рівень вище;
   **+ Сторінка**, **+ Посилання**, **Видалити**. Позначка «не заповнено» зникає, коли ви заповнили сторінку.
4. **Файли** — завантаження, пошук, видалення, копіювання коду для вставки.
5. **Налаштування сайту** — назва, адреса, фото на головній, кнопки, швидкий доступ, соцмережі, відео, банери
   (е-щоденники), групи посилань (партнери).
6. Натисніть жовту кнопку **«Опублікувати зміни»** — усі правки потрапляють на сайт одним записом.
   До цього моменту зміни зберігаються лише в браузері (закриття вкладки їх скасує — панель попередить).

Якщо хтось інший встиг змінити ті самі матеріали, панель не перезапише чужу роботу, а попросить оновити сторінку.

## 4. Перенесення решти матеріалів зі старого сайту

З ваших архівів перенесено **головну сторінку** (текст, зображення, банери, відео, соцмережі) та **«Історію закладу»**.
Інші 60 сторінок мають створене місце в меню й позначку «не заповнено» з посиланням на оригінал.
Наповнити їх можна двома способами:

**А. Автоматично (рекомендовано).** На комп’ютері з Python 3.9+:

```bash
pip install beautifulsoup4 requests
cd dmlsayt-site
python tools/migrate_google_sites.py --list            # що ще не перенесено
python tools/migrate_google_sites.py --all             # перенести все
python tools/migrate_google_sites.py --only statut     # або окремі сторінки
```

Скрипт завантажує сторінки зі старого сайту, перетворює їх на Markdown, зберігає зображення в `uploads/pages/…`,
вбудовує документи з Google Диску та відео, замінює посилання між сторінками на нові й знімає позначку «не заповнено».
Якщо якась сторінка вийшла порожньою, повторіть з `--render` (потрібно `pip install playwright && playwright install chromium`)
або збережіть сторінку в браузері («Зберегти як… → Веб-сторінка повністю») як `saved/<адреса>.html` і запустіть
`python tools/migrate_google_sites.py --all --from-dir saved`.
Після цього завантажте зміни в репозиторій (`git add . && git commit -m "Перенесення" && git push`, або GitHub Desktop).

**Б. Вручну** — у панелі відкрийте сторінку, вставте текст, додайте файли кнопкою «Файл».

> **Документи на Google Диску** скрипт вбудовує як є (вони продовжать відкриватися, доки лежать на Диску).
> Щоб зберігати їх у самому репозиторії — скачайте й завантажте у вкладці «Файли».

## 5. Важливо знати

* **Публічність.** Усе, що лежить у репозиторії, бачить будь-хто. Не завантажуйте документи з персональними даними
  без правових підстав (наприклад, перевірте, що можна публікувати «Список дітей, зарахованих до 1 класу»).
* **Розмір файлів.** До ~25 МБ зручно; жорсткий ліміт GitHub — 100 МБ на файл. Великі відео краще розмістити на YouTube
  і вставити кнопкою «Відео».
* **Адреси сторінок** мають вигляд `…/#/statut`. Старий сайт у пошукових системах теж був закритий від індексації (`noindex`).
* **Токен** зберігається лише в браузері (за замовчуванням — до закриття вкладки). Не вмикайте «Запам’ятати» на чужих комп’ютерах.
  Якщо токен загубився чи потрапив не до тих рук — видаліть його на GitHub та створіть новий.
* **Резервні копії.** Кожна публікація — це запис в історії GitHub (*вкладка Commits*), звідки можна відновити будь-яку версію.
* Шрифти (Google Fonts), відео YouTube і стрічка Facebook підвантажуються з зовнішніх сервісів; решта працює автономно.

## 6. Перегляд на власному комп’ютері

```bash
cd dmlsayt-site
python -m http.server 8000     # відкрийте http://localhost:8000
```
(Відкривати `index.html` подвійним кліком не можна — браузер забороняє читати файли з диска.)
